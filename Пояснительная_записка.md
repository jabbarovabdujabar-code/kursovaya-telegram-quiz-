# Пояснительная записка

## 1. Тема и цель проекта
**Тема:** «Интерактивный справочник‑викторина по философии» (реализация в формате Telegram‑бота).

**Цель проекта:** разработать интерактивную викторину на JavaScript, которая:
- загружает вопросы и варианты ответов из внешнего файла;
- последовательно задаёт вопросы пользователю;
- ведёт учёт набранных очков;
- позволяет добавлять новые вопросы в базу.

## 2. Обоснование выбора решения
Telegram‑бот выбран как удобный интерфейс взаимодействия с пользователем: викторину можно проходить с телефона или ПК без установки отдельного приложения.

При этом ключевые требования варианта «Викторина с вопросами из файла» соблюдены:
- база вопросов хранится во внешнем JSON;
- логика выдачи вопросов последовательная;
- ведётся статистика пользователя;
- реализовано добавление новых вопросов (ограничено администратором);
- применяются массивы, объекты и строки, предусмотрена обработка ошибок.

## 3. Требования и их реализация
### 3.1. Загрузка данных из файла
- Формат: **JSON**.
- Файл: `src/data/questions.json`.
- Структура данных: массив объектов.

Пример объекта вопроса:
- `id` — строковый идентификатор
- `question` — текст вопроса
- `options` — массив из 4 вариантов ответа
- `correctAnswer` — индекс правильного ответа (0..3)
- `explanation` — пояснение после ответа
- `tags` — массив меток (необязательно)

### 3.2. Взаимодействие с пользователем
Интерфейс реализован в Telegram:
- команды (`/start`, `/quiz`, `/stats`, `/reset`);
- варианты ответа выводятся **inline‑кнопками** (InlineKeyboard);
- после ответа показывается обратная связь: верно/неверно + пояснение.

### 3.3. Логика викторины
- Вопросы задаются по одному.
- За каждый правильный ответ начисляется 1 очко.
- По завершении вопросов выводится итоговая статистика.

### 3.4. Добавление новых вопросов
Команда доступна только администратору (ID хранится в `ADMIN_ID` в `.env`).

Формат:

`/add_question Вопрос? | Вариант1 | Вариант2 | Вариант3 | Вариант4 | 2 | Пояснение`

Где `2` — номер правильного варианта (1..4).

### 3.5. Хранение прогресса
Чтобы пользователь мог смотреть статистику и не терять результаты:
- используется файл `src/data/sessions.json`.

Хранится:
- `stats.total` — всего ответов
- `stats.correct` — правильных
- `stats.streak` — серия правильных ответов подряд

## 4. Используемые структуры данных (требование: массивы, объекты, строки)
### 4.1. Массивы
- массив вопросов (из `questions.json`)
- массив `options` (варианты ответа)
- массив порядка вопросов `order` (перемешанная последовательность)

### 4.2. Объекты
- объект вопроса (`{ id, question, options, correctAnswer, ... }`)
- объект сессий пользователей (ключ — userId)
- объект статистики пользователя

### 4.3. Строки
- тексты вопросов и ответов
- парсинг команды `/add_question`
- формирование сообщений для отправки в чат

## 5. Архитектура и структура проекта
Проект разбит на логические модули:
- `src/index.js` — точка входа, обработчики команд и callback‑кнопок
- `src/bot/quiz.js` — логика викторины (старт/получение текущего вопроса/применение ответа)
- `src/storage/questions.js` — загрузка/сохранение базы вопросов, парсинг добавления вопроса
- `src/storage/sessions.js` — загрузка/сохранение прогресса пользователей
- `src/utils/format.js` — форматирование статистики

Такое разделение упрощает поддержку и соответствует критерию «архитектура проекта».

## 6. Алгоритм работы (кратко)
1. Пользователь вводит `/quiz`.
2. Если викторина не активна — формируется перемешанный порядок вопросов и начинается с первого.
3. Бот отправляет вопрос и 4 inline‑кнопки с вариантами.
4. Пользователь нажимает кнопку.
5. Бот сравнивает выбранный индекс с `correctAnswer`, обновляет статистику.
6. Бот отправляет обратную связь и показывает следующий вопрос.
7. При завершении — вывод итоговой статистики.

## 7. Обработка ошибок и валидация
Реализовано:
- проверка наличия `BOT_TOKEN` при запуске;
- проверка формата добавления вопроса (количество частей, диапазон правильного ответа 1..4);
- обработка ситуации, когда викторина не запущена, но нажата кнопка ответа;
- корректная работа при завершении списка вопросов.

## 8. Тестирование (сценарии)
Проверены основные сценарии:
1. `/start` — бот отвечает подсказкой по командам.
2. `/quiz` — старт, вопросы задаются по одному.
3. Выбор правильного/неправильного ответа — корректная обратная связь.
4. `/stats` — статистика обновляется.
5. `/reset` — сброс прогресса.
6. `/add_question ...`:
   - не админ → отказ;
   - админ, неверный формат → сообщение об ошибке;
   - админ, корректный формат → вопрос добавлен в `questions.json`.

## 9. Инструкция по запуску
Инструкция для запуска приведена в `README.md` репозитория.

Кратко:
1. `npm install`
2. создать `.env` по примеру `.env.example`
3. `npm start`

## 10. Заключение
В результате разработан Telegram‑бот, реализующий интерактивную викторину по философии. Проект соответствует ключевым требованиям: работа с данными из файла JSON, последовательная логика вопросов, подсчёт очков, добавление новых вопросов, применение массивов/объектов/строк, обработка ошибок и наличие документации.
